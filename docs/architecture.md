# 架构与实机检查

## 边界

`engine.rs` 是确定性状态机，只接受 Linux 物理键码和显式时间增量，输出语义动作。没有线程、系统调用或隐式时钟。它拥有模式、按键前缀、标记、拖选按钮、连续动作和输入透传状态。

`grid.rs` 区分 Block 和 Precision 工具。f 创建 Block，仅显示当前输出的 5×5；有效字母返回区块中心，控制器立即提交并回到 Normal。普通模式 Tab 创建以当前指针为中心的独立 Precision 区域，总尺寸为输出尺寸的 1/5，从 4×4 开始，不移动指针。靠近边缘时平移区域以保持尺寸并避免越界；不再引用 f 的区块或历史帧。后续 3×3、2×2 保留原有 hjkl/Tab 精细控制，Tab 深入也以选中位置为中心计算区域。Precision 的回退边界是 4×4，z 不会重新打开 f。两个工具各有自己的取消原点和跳转记录。

`desktop.rs` 使用当前可执行文件的只读子命令，在两秒超时内检查 Wayland 与 layer-shell 协议；拒绝 root 浮层。`run` 启动同一可执行文件的 `hud` 子进程，等待就绪握手后才进入输入后端。浮层故障不参与按键处理；输入后端可独立通过 --no-hud 运行。

`linux.rs` 是设备适配层。它枚举并过滤物理键盘、先创建两个虚拟输入设备、等待合成器发现设备，再独占捕获键盘。Insert 模式事件通过虚拟键盘透传；其他模式只发送控制器产生的动作。多键盘按键使用引用计数合并；一个键盘释放按键不会停止另一个键盘仍然持有的动作。

虚拟键盘与虚拟指针是独立设备，避免设备被分类成混合键鼠。绝对指针暴露 ABS_X/ABS_Y、三个鼠标按钮和双轴滚轮，使用 POINTER 属性。合成器负责将设备的绝对范围映射到输出；程序不把原始实体鼠标增量误当成桌面坐标。

一个 `poll` 事件循环负责设备输入、移动积分、滚动和超时。移动速度按实际时间积分，对角线归一化；单次积分上限 50ms，避免进程卡顿后光标大幅跳跃。移动时按配置更新，静止时最多每 250ms 检查超时和退出，不为空闲状态启动移动线程。

设备对象的 Drop 负责取消抓取，输出对象的 Drop 尽力释放所有虚拟按键和按钮。SIGINT、SIGTERM、SIGHUP 设置退出标志，由正常事件循环收尾。进程被 SIGKILL 时内核关闭 fd 并撤销抓取，用户态无法执行清理；需要重新启动浮层以清除异常退出遗留的状态显示。

`status.rs` 用用户独占目录、flock 和原子 rename 发布 JSON 状态。状态中只有模式、速度、虚拟位置、命令前缀和提示，不保存 Insert 输入。位置更新最多约 25Hz；内容未变化时不重写文件。

`src/hud/` 是原生 Rust Wayland 客户端，禁用 smithay-client-toolkit 的 xkbcommon/calloop 默认特性，使用纯 Rust Wayland 后端。每个输出独立创建一个全屏 overlay layer surface，键盘交互为 None，鼠标输入区域为空，exclusive zone 为 -1。状态条与网格绘制到同一个表面；没有 transient popup。所有表面持续映射，退出网格时提交透明像素，不通过 map/unmap 触发窗口动画。

`render.rs` 通过 wl_shm ARGB8888 软件绘制透明网格与状态条，颜色使用预乘 alpha。DejaVu Sans Mono 字体编译进二进制，无字体或 GPU 依赖。输出逻辑尺寸与 buffer scale 分离；网格按控制器整数分区绘制，减去当前输出偏移。字母在网格左上角，三级和四级不显示字符。每个输出只在配置或相关状态改变时重绘，非当前输出保持透明。状态消失时清空浮层。25ms poll 同时处理 Wayland 事件和状态更新，SIGTERM 等正常收尾。

`displays.rs` 优先使用已有 KDE 工具 / niri IPC 读取布局，也支持当前二进制 `native-displays` 子命令直接读取 Wayland xdg-output 逻辑布局，不需要安装桌面辅助命令；查询有超时。控制器保留全局坐标，输出端将点转换到固定 uinput 绝对轴范围。Space 独立循环输出并居中；布局变化时释放拖选、结束网格并清除旧标记。KDE 活动输出查询仍使用可选 qdbus6；缺失时保留内部选屏，niri 无外部命令依赖。

默认 GNU 构建依赖 libc/libgcc；musl 构建可生成静态单文件。不再包含 QML 或调用 qml 程序。权限规则、用户服务和安装器属于可选配置材料，不是浮层运行时依赖。

## 内嵌初始化与用户服务

`setup` 负责一次性权限配置。普通用户通过 sudo / pkexec 重新执行当前二进制的 root 初始化分支，仅向调用用户 UID 授权；目标账户由 getpwuid_r 验证。管理员命令从固定系统目录查找，不使用 shell 拼接。内核接口验证成功后才写入组、udev 和模块加载配置，避免内核升级未重启时留下半套权限配置。

`setup/acl.rs` 通过 fgetxattr / fsetxattr 编解码 Linux POSIX ACL，不依赖 libacl 或 setfacl。只接受已打开字符设备，保留其他 ACL 条目的有效权限，扩大 mask 时避免意外放宽其他用户或组权限。配置文件和用户二进制都通过临时文件与 rename 原子替换。

`service.rs` 安装一个 systemd 用户服务，以 `run` 同时管理控制器及其 HUD 子进程。服务使用 Type=notify；输入捕获和状态发布成功后，通过 Unix datagram 发送 READY=1，`start` 等待此信号。设备/HUD 启动失败不会报告就绪。普通退出不会自动重启；异常退出受次数限制并可重启。停止服务按控制组发送 SIGTERM，输入后端正常释放设备。

服务安装启用下次图形登录自启动，但不当场启动。显示连接设置只保存在用户运行时目录的单元 drop-in，不污染用户管理器的全局环境；更新程序使用原子替换，对已运行实例不会强行重启。旧版独立 HUD 服务存在时停用并停止。命令行初始化/服务管理通过隔离 HOME、模拟 sudo/pkexec/systemctl 和只读 systemd 单元校验测试，避免开发测试修改真实系统。

## 在真实桌面验证

自动化检查已覆盖纯状态机与 CLI；下列检查需要可用的 `/dev/input`、`/dev/uinput` 和实际合成器。先只捕获一个键盘，保留另一个输入方式或终端，前台运行 `vimouse run --device ...`。

1. 用 `doctor` 检查访问条件，启动时松开所有键。确认日志列出的设备正确，Insert 中可正常输入、使用修饰键和输入法。
2. 按 Caps 进入 Normal。确认光标到中心，未将 Caps 发送给应用。测试 hjkl、对角线、三档速度、边界和停止动作。
3. 测试左/右/中键、菜单映射、滚动、marks 和 gg/gc/ge/zt/zz/zb。确认绝对设备的分类与映射；若坐标对应错误，检查桌面显示器映射和 `screen` 配置。
4. 在文本编辑器中测试 v 拖选、Ctrl+v 中键拖动；分别用 v、i、Esc、Caps、超时、Ctrl+Alt+Esc、SIGTERM 结束，确认没有按钮卡住。
5. 测试 Shift+i、Alt+Tab、Ctrl+Tab；从命令模式和 Select 中使用紧急退出组合键。确认应用没有残留修饰键。
6. 打开浮层，确认不改变原应用焦点、能点击穿透、Insert 时隐藏，命令、速度和模式显示一致。在 Plasma Wayland 确认底部固定及全屏应用上的覆盖层行为。
7. 测试键盘断开时退出并释放控制；多键盘同时按同一个移动键时，释放其中一个不会提前停止。重新连接后重启控制器。
8. 测试 f → a–y 后立即进入 Normal，并能直接 hjkl 连续移动。再按普通 Tab 确认 4×4 区域以当前指针为中心展开，跨原 f 区块边界不吸附，屏幕四角不越界，初始指针不跳动；a–p → hjkl → Tab → hjkl → Space 完成。验证 z 不回到 f、取消恢复 Tab 原点、字母边界、跨屏偏移、长按和最终层级停止。

后续优先事项是实机验证和修正合成器差异，然后再扩展输出拓扑、全局指针同步、热插拔、按键映射配置和 Windows 后端。
