# 架构与实机检查

## 边界

`engine.rs` 是确定性状态机，只接受 Linux 物理键码和显式时间增量，输出语义动作。没有线程、系统调用或隐式时钟。它拥有当前交互上下文、标记及连续动作；物理按键与透传记录属于跨上下文的 InputState。

`engine/context.rs` 用携带数据的 Context 枚举表达互斥上下文：Normal/Visual 持有前缀，Visual 持有拖拽按钮，Command 持有文本，Grid 持有网格；Insert、Select、Marks、Help 无额外载荷。公开 Mode 仅作为状态投影，保留现有 JSON 格式。`global.rs` 处理紧急释放、Caps 与输入透传，`pointer.rs` 处理 Normal/Visual，`tools.rs` 分派独立工具。统一 enter/exit 负责停止持续动作、释放拖拽和透传键，避免各处理器直接改模式留下旧状态。Visual 用 Enter 结束也停止持续移动；Select 的 Esc 与 q 都向应用发送 Escape，Shift+q 只退出上下文。

`geometry.rs` 提供逻辑 Point/Rect，显示器、标记和网格共用，不依赖控制器。

`grid.rs` 区分 Block 和 Precision 工具。f 创建 Block，仅显示当前输出的 5×5；有效字母返回区块中心，控制器立即提交并回到 Normal。普通模式 Tab 创建以当前指针为中心的独立 Precision 区域，总尺寸为输出尺寸的 1/5，从 4×4 开始，不移动指针。靠近边缘时平移区域以保持尺寸并避免越界；不再引用 f 的区块或历史帧。后续 3×3、2×2 保留原有 hjkl/Tab 精细控制，Tab 深入也以选中位置为中心计算区域。Precision 的回退边界是 4×4，z 不会重新打开 f。两个工具各有自己的取消原点和跳转记录。

`desktop.rs` 使用当前可执行文件的只读子命令，在两秒超时内检查 Wayland 与 layer-shell 协议；拒绝 root 浮层。`run` 启动同一可执行文件的 `hud` 子进程，等待就绪握手后才进入输入后端。HudProcess 明确区分禁用、运行和已退出状态。控制器循环检查子进程，浮层意外退出时回收子进程并报错，释放输入控制；服务可按失败策略重启。只有显式 --no-hud 才允许没有浮层独立运行。demo 在等待标准输入时同样检查浮层健康。

`linux.rs` 是设备适配层。它枚举并过滤物理键盘、先创建两个虚拟输入设备、等待合成器发现设备，再独占捕获键盘。Insert 模式事件通过虚拟键盘透传；其他模式只发送控制器产生的动作。多键盘按键使用引用计数合并；一个键盘释放按键不会停止另一个键盘仍然持有的动作。

虚拟键盘与虚拟指针是独立设备，避免设备被分类成混合键鼠。绝对指针暴露 ABS_X/ABS_Y、三个鼠标按钮和双轴滚轮，使用 POINTER 属性。合成器负责将设备的绝对范围映射到输出；程序不把原始实体鼠标增量误当成桌面坐标。

一个 `poll` 事件循环负责设备输入、移动积分、滚动和超时。持续按向屏幕外侧时，边界夹取不会停止 Pointer 动作；Linux 输出层利用已有的最小 ABS 变化重新确认目标位置，使合成器的边缘回推与停留检查有后续事件。松开方向键后停止，不引入逻辑坐标横向摆动。移动速度按实际时间积分，对角线归一化；单次积分上限 50ms，避免进程卡顿后光标大幅跳跃。移动时按配置更新，静止时最多每 250ms 检查超时和退出，不为空闲状态启动移动线程。

设备对象的 Drop 负责取消抓取，输出对象的 Drop 尽力释放所有虚拟按键和按钮。SIGINT、SIGTERM、SIGHUP 设置退出标志，由正常事件循环收尾。进程被 SIGKILL 时内核关闭 fd 并撤销抓取，用户态无法执行清理；需要重新启动浮层以清除异常退出遗留的状态显示。

`status.rs` 用用户独占目录、flock 和原子 rename 发布 JSON 状态。状态中只有模式、速度、虚拟位置、命令前缀和提示，不保存 Insert 输入。位置更新最多约 25Hz；内容未变化时不重写文件。

`src/hud/` 是原生 Rust Wayland 客户端，禁用 smithay-client-toolkit 的 xkbcommon/calloop 默认特性，使用纯 Rust Wayland 后端。每个输出独立创建一个全屏 overlay layer surface，键盘交互为 None，鼠标输入区域为空，exclusive zone 为 -1。状态条与网格绘制到同一个表面；没有 transient popup。所有表面持续映射，退出网格时提交透明像素，不通过 map/unmap 触发窗口动画。

`render.rs` 通过 wl_shm ARGB8888 软件绘制透明网格与状态条，颜色使用预乘 alpha。DejaVu Sans Mono 字体编译进二进制，无字体或 GPU 依赖。输出逻辑尺寸与 buffer scale 分离；网格按控制器整数分区绘制，减去当前输出偏移。字母按字形可见区域居中在各格实际鼠标落点上，三级和四级不显示字符。Normal/Visual/Select 仅显示右下角 156×30 的模式与速度胶囊；Command 展开完整命令条；Insert/Grid 不显示状态 UI。胶囊右边距 16、底边距 64 逻辑像素，命令条也保留 64 底边距。胶囊只在模式、速度或 mark 保存错误变化时重绘，不随坐标或消息变化重绘。每个输出只在配置或相关状态改变时重绘，非当前输出保持透明。状态消失时清空浮层。Marks 与 Help 为独立控制器模式，进入时清除持续动作；Marks 将带显示器身份的落点发布到状态，各输出独立绘制自己的落点与字母标记，不显示额外说明面板或胶囊；Help 只在当前输出居中显示。二者使用现有透明表面，无原生新窗口及 map/unmap。标记选择只跳转不点击，Esc 退出；数字调速只在 Normal 无前缀时生效。25ms poll 同时处理 Wayland 事件和状态更新，SIGTERM 等正常收尾。

`displays.rs` 优先使用已有 KDE 工具 / niri IPC 读取布局，也支持当前二进制 `native-displays` 子命令直接读取 Wayland xdg-output 逻辑布局，不需要安装桌面辅助命令；查询有超时。控制器保留全局坐标，输出端将点转换到固定 uinput 绝对轴范围。Space 独立循环输出并居中；布局变化时释放拖选、结束网格，清除临时跳转历史，保留命名标记。KDE 活动输出查询仍使用可选 qdbus6；缺失时保留内部选屏，niri 无外部命令依赖。

默认 GNU 构建依赖 libc/libgcc；musl 构建可生成静态单文件。不再包含 QML 或调用 qml 程序。权限规则、用户服务和安装器属于可选配置材料，不是浮层运行时依赖。

## 命名标记状态

`marks.rs` 定义版本化 JSON 与纯数据 Mark（显示器名称、逻辑相对 x/y），Engine 保存这些记录并按当前布局解析；布局变化不删除 mark，找不到同名显示器则拒绝跳转，避免落到其他输出。`previous` 仍是仅在内存中的临时跳转位置。mark 修订号只在显式设置时增加。

Linux 后端在创建虚拟设备/捕获输入前加载状态，逐次按键处理后将新修订的完整快照提交给 `marks/worker.rs` 的 SaveWorker。专用线程串行保存并合并尚未处理的快照；邮箱锁不覆盖任何文件操作，输入循环不执行 mark 的 fsync。保存结果带修订号返回，旧结果不会覆盖新修订的状态。Store 使用 XDG_STATE_HOME（默认 HOME/.local/state），限制文件大小、格式版本、标记名和坐标范围，拒绝非普通文件及最终文件符号链接。保存使用同目录私有临时文件、fsync、rename、目录 fsync；不在指针更新时写磁盘。读取异常保留文件并拒绝启动，写入异常不打断输入控制，保留内存记录并记录日志，以跨上下文的 mark_save_error 发布给 HUD：普通胶囊显示红色感叹号，命令条和帮助卡片显示保存失败。下一次编辑重新提交，最新修订保存成功才清除错误。run_input 的设备作用域先结束，再由外层等待保存线程刷完最新快照；异常退出同样先释放键盘和虚拟按钮。demo 不连接 Store，验证脚本不会改写用户真实标记。

## 内嵌初始化与用户服务

`setup` 负责一次性权限配置。普通用户通过 sudo / pkexec 重新执行当前二进制的 root 初始化分支，仅向调用用户 UID 授权；目标账户由 getpwuid_r 验证。管理员命令从固定系统目录查找，不使用 shell 拼接。内核接口验证成功后才写入组、udev 和模块加载配置，避免内核升级未重启时留下半套权限配置。

`setup/acl.rs` 通过 fgetxattr / fsetxattr 编解码 Linux POSIX ACL，不依赖 libacl 或 setfacl。只接受已打开字符设备，保留其他 ACL 条目的有效权限，扩大 mask 时避免意外放宽其他用户或组权限。配置文件和用户二进制都通过临时文件与 rename 原子替换。

Cargo 负责安装与更新可执行文件。`service.rs` 将调用它的当前可执行文件绝对路径注册为一个 systemd 用户服务，以 `run` 同时管理控制器及其 HUD 子进程。服务使用 Type=notify；输入捕获和状态发布成功后，通过 Unix datagram 发送 READY=1，`start` 等待此信号。设备/HUD 启动失败不会报告就绪。普通退出不会自动重启；异常退出受次数限制并可重启。停止服务按控制组发送 SIGTERM，输入后端正常释放设备。

服务安装启用下次图形登录自启动，但不当场启动。显示连接设置只保存在用户运行时目录的单元 drop-in，不污染用户管理器的全局环境；服务注册不复制可执行文件，兼容 Cargo 默认或自定义安装目录；独立 `install` 命令仍为手动单文件安装提供原子复制。更新程序后需停止再启动服务，不强行重启正在运行的实例。旧版独立 HUD 服务存在时停用并停止。命令行初始化/服务管理通过隔离 HOME、模拟 sudo/pkexec/systemctl 和只读 systemd 单元校验测试，避免开发测试修改真实系统。

## 在真实桌面验证

自动化检查已覆盖纯状态机与 CLI；下列检查需要可用的 `/dev/input`、`/dev/uinput` 和实际合成器。先只捕获一个键盘，保留另一个输入方式或终端，前台运行 `vimouse run --device ...`。

1. 用 `doctor` 检查访问条件，启动时松开所有键。确认日志列出的设备正确，Insert 中可正常输入、使用修饰键和输入法。
2. 按 Caps 进入 Normal。确认光标到中心，未将 Caps 发送给应用。测试 hjkl、对角线、三档速度、边界和停止动作。
3. 测试左/右/中键、菜单映射、滚动、marks 和 gg/gc/ge/zt/zz/zb。确认绝对设备的分类与映射；若坐标对应错误，检查桌面显示器映射和 `screen` 配置。
4. 在文本编辑器中测试 v 拖选、Ctrl+v 中键拖动；分别用 v、i、Esc、Caps、超时、Ctrl+Alt+Esc、SIGTERM 结束，确认没有按钮卡住。
5. 测试 Shift+i、Alt+Tab、Ctrl+Tab；从命令模式和 Select 中使用紧急退出组合键。确认应用没有残留修饰键。
6. 打开浮层，确认不改变原应用焦点、能点击穿透、Insert 时隐藏，命令、速度和模式显示一致。确认普通模式只显示右下角胶囊，三档速度及拖选/菜单模式正确，命令模式展开输入条，退出命令后收起；在 Plasma Wayland 确认与任务栏的位置及全屏应用上的覆盖层行为。
7. 测试键盘断开时退出并释放控制；多键盘同时按同一个移动键时，释放其中一个不会提前停止。重新连接后重启控制器。
8. 测试 f → a–y 后立即进入 Normal，并能直接 hjkl 连续移动。再按普通 Tab 确认 4×4 区域以当前指针为中心展开，跨原 f 区块边界不吸附，屏幕四角不越界，初始指针不跳动；a–p → hjkl → Tab → hjkl → Space 完成。验证 z 不回到 f、取消恢复 Tab 原点、字母边界、跨屏偏移、长按和最终层级停止。

后续优先事项是实机验证和修正合成器差异，然后再扩展输出拓扑、全局指针同步、热插拔、按键映射配置和 Windows 后端。
